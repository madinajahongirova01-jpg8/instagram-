# ADR-011: Социальные функции во frontend

**Статус:** принято · **Дата:** 2026-10-23

## Проблема

ТЗ (раздел 4) и `AI_RULES.md` (правило 3) разрешали во frontend только 6 страниц: Login, Register, Profile, Logout, Change Password, Forgot Password. Backend уже умеет почти всё, что нужно социальной сети (посты, stories, reels, лента, поиск, explore, подписки, уведомления, сообщения), но пользователь не может этим пользоваться через сайт.

Владелец проекта решила расширить frontend основными социальными функциями (Core Social Features) с новым дизайном: тёмная и светлая тема по двум макетам из папки `img/`.

## Рассмотренные варианты

1. Оставить 6 страниц, функции проверять только через Swagger.
2. **Добавить ограниченный набор страниц для Core Social Features**; Messages и Settings — отдельными решениями позже.
3. Сразу перенести все функции backend во frontend (включая сообщения, звонки, настройки приватности).

## Принятое решение

Вариант 2.

### Новые страницы

| Путь | Что это |
|---|---|
| `/` | Главная: stories + персональная лента (раньше — только редирект на `/profile`) |
| `/explore` | Интересное: сетка популярных постов и reels от неподписанных + тренды хэштегов |
| `/explore/tags/[name]` | Посты по хэштегу |
| `/search` | Поиск пользователей, постов, хэштегов + история запросов (на desktop поиск также открывается из верхней строки) |
| `/reels` | Вертикальная лента reels |
| `/create` | Создание: пост / story / reel |
| `/p/[id]` | Отдельный пост с комментариями |
| `/stories/[username]` | Полноэкранный просмотр stories |
| `/profile/[username]` | Чужой профиль (расширение существующей страницы Profile; `/profile` — свой профиль) |

Существующие 6 страниц остаются и получают обе темы. Вкладки Posts / Reels / Saved — часть страницы профиля, не отдельные страницы. Уведомления — выпадающая панель из иконки сердца (без отдельной страницы).

### Новые возможности backend (недостающие endpoints)

Проверено по Swagger (72 пути) и коду контроллеров. Не хватает:

| Что | Endpoint | Зачем |
|---|---|---|
| Сохранённые посты | `POST /api/posts/:id/save`, `DELETE /api/posts/:id/save`, `GET /api/users/me/saved?cursor&limit` + поле `PostDto.savedByMe` + таблица `SavedPost` (миграция) | кнопка «bookmark» и вкладка Saved |
| Контакты с онлайн-статусом | `GET /api/users/me/contacts` | правая колонка «Контакты»: собеседники личных диалогов + `online` / `lastSeenAt` с учётом `showOnlineStatus` и блокировок. Это те же люди, которым backend уже рассылает `presence:online/offline`, поэтому статус обновляется в реальном времени |
| Непрочитанные сообщения | `GET /api/conversations/unread-count` | бейдж у пункта «Сообщения» |

Всё остальное уже есть: `GET /feed`, `GET /feed/explore`, `GET /search`, `GET /search/hashtags/:name/posts`, `GET /users/suggested`, `GET /stories/feed`, `GET /reels`, `GET /notifications/unread-count` и т. д.

Каждый новый endpoint: DTO-валидация, проверка прав и приватности (`VisibilityService`), Swagger, unit- и e2e-тесты, описание в `docs/SPEC`.

### Темы

- Цвета — CSS-переменные (токены) в `globals.css` для `:root` (светлая) и `.dark` (тёмная), подключены в Tailwind 4 через `@theme inline`. В компонентах нет жёстких цветов.
- Выбор темы: `light` / `dark` / `system` (по умолчанию `system`), хранится в `localStorage` (чтение/запись в `try/catch`).
- Без мигания: маленький inline-скрипт в `<head>` ставит класс `dark` до первой отрисовки. Новая зависимость (next-themes) не нужна.

### Layout

- Desktop (≥ 1280 px): 3 колонки — сайдбар, центр, правая колонка.
- Планшет (768–1279 px): сайдбар + центр, правая колонка скрыта.
- Мобильный (< 768 px): сверху логотип и иконки, снизу панель навигации. Без горизонтальной прокрутки.

### Realtime

Frontend подключается к существующему Socket.io (`socket.io-client`, чистый JS, уже установлен в monorepo). События `notification:new`, `message:new`, `presence:online/offline` обновляют бейджи, счётчики своих постов (лайк/комментарий от другого человека) и онлайн-статус контактов через инвалидацию тегов RTK Query.

## Причины выбора

- Backend уже готов и протестирован — frontend делает его полезным.
- Ограниченный список страниц сохраняет правило «не добавлять лишнего».
- Сообщения (чаты, звонки) — большой отдельный объём; их лучше делать отдельным ADR.

## Последствия

- `AI_RULES.md` (правило 3), ТЗ (раздел 4), `ROADMAP.md` обновлены.
- Пункты «Сообщения» в сайдбаре показывают бейдж непрочитанных, но страница Messages в этот ADR не входит (см. «Открытый вопрос»).
- Лента остаётся хронологической (так работает `feed`-модуль, SPEC FEED); персональный алгоритм — в ROADMAP. Explore не имеет пагинации (backend отдаёт 30 постов и 20 reels).
- Счётчики лайков у **чужих** постов не обновляются в реальном времени (backend не рассылает такие события); обновляются при следующем запросе.
- История поиска хранится только в браузере (`localStorage`, ключ на пользователя), на сервер не отправляется.
- Промо-карточка в сайдбаре — статический текст из `messages/*.json`, кнопка ведёт на `/create`.
- Подпись в «Рекомендациях» — полное имя пользователя (backend не отдаёт причину рекомендации, выдумывать не будем).

## Решение по «Сообщениям»

Пункт «Сообщения» в навигации показывает бейдж непрочитанных, но неактивен (подсказка «скоро») до отдельного ADR о странице Messages.
