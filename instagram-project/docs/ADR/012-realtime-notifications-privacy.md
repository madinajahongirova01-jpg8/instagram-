# ADR-012: Уведомления, приватность и сообщения во frontend

**Статус:** принято (владелец проекта согласовала заранее) · **Дата:** 2026-10-23

## Проблема

После ADR-011 у пользователя есть лента, профиль, stories, reels и поиск, но нет:

- страницы уведомлений и их настроек;
- настроек приватности (закрытый аккаунт, блокировки, жалобы, кто может писать, кто видит stories);
- личных сообщений (пункт «Сообщения» был неактивен).

Backend уже умеет большую часть этого (ADR-008, ADR-009), но не хватает: «Близких друзей» и скрытия stories от отдельных людей, аудитории stories, варианта «писать могут только мои подписки».

## Рассмотренные варианты

1. Делать каждую функцию отдельным ADR.
2. **Один ADR на три связанные области: уведомления, приватность, сообщения (+ звонки, если хватит времени).**

## Принятое решение

Вариант 2.

### Новые страницы

| Путь | Что это |
|---|---|
| `/notifications` | Список уведомлений: «Сегодня / Ранее», прочитать одно / все, запросы на подписку (принять / отклонить) |
| `/settings` | Настройки: приватность аккаунта, кто может писать, онлайн-статус, уведомления по типам, «Близкие друзья», скрыть stories от людей, заблокированные |
| `/messages`, `/messages/[id]` | Список диалогов и открытый чат; на телефоне — по одному экрану |

Пункт «Сообщения» в сайдбаре становится активным.

### Изменения backend

| Что | Как |
|---|---|
| Аудитория stories | `Story.audience`: `EVERYONE` / `FOLLOWERS` / `CLOSE_FRIENDS` (enum `StoryAudience`) |
| Близкие друзья | таблица `CloseFriend`; `GET /api/privacy/close-friends`, `PUT` / `DELETE /api/privacy/close-friends/:userId` |
| Скрыть stories от человека | таблица `StoryHide`; `GET /api/privacy/story-hidden`, `PUT` / `DELETE /api/privacy/story-hidden/:userId` |
| «Писать могут только мои подписки» | новое значение `FOLLOWING` в enum `Audience` (я подписана на отправителя); проверяется и при создании диалога, и при каждой отправке |
| Уведомления о сообщениях | не попадают в список и счётчик уведомлений (у сообщений свой бейдж) |

Видимость stories проверяется на backend в ленте stories, в stories профиля и при отметке просмотра. Всё покрыто e2e-тестами.

### Realtime

Используется существующий Socket.io (ADR-008). Frontend держит **одно** соединение (`lib/socket.ts`); события только инвалидируют или точечно меняют кэш RTK Query (второго кэша нет).

### Звонки (WebRTC)

Делаются только если всё выше готово и стабильно. Иначе — ROADMAP. Без TURN-сервера звонок работает только на localhost / в одной сети.

## Последствия

- `AI_RULES.md` (правило 3), ТЗ, ROADMAP, SPEC PRIVACY, STORIES, MESSAGES, NOTIFICATIONS обновлены.
- Жалобы сохраняются в таблицу `Report`; админ-панели нет (ROADMAP).
- «Доставлено» означает «сохранено на сервере» (сообщение пришло через REST); «прочитано» — по `lastReadAt` собеседника, если он не выключил `showReadReceipts`.
