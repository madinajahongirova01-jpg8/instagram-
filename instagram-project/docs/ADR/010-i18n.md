# ADR-010: Интернационализация (next-intl)

**Статус:** принято · **Дата:** 2026-10-23

## Проблема

Пользователи — в Таджикистане: нужны английский (как в дизайне), русский и таджикский.

## Рассмотренные варианты

1. Только английский.
2. **next-intl с сегментом `[locale]`.**
3. Самописный словарь.

## Принятое решение

- Локали `en` (по умолчанию), `ru`, `tg` — `packages/shared/src/i18n.ts`.
- `localePrefix: 'as-needed'`: английский без префикса (`/login`), остальные — `/ru/login`, `/tg/login`. Ссылки из писем (`/login?verifyToken=…`) работают без префикса.
- Сообщения: `apps/web/messages/{en,ru,tg}.json`; плюральные формы ICU.
- `middleware.ts` определяет язык; переключатель языка — `LocaleSwitcher`.
- Ошибки валидации backend приходят на английском; частые случаи (неверный пароль, 429, сеть, неверный токен) переводятся на frontend.

## Причины выбора

next-intl — стандартное решение для App Router, поддерживает статическую генерацию страниц по локалям.

## Последствия

Для нового текста нужно добавить ключ во все три файла, иначе next-intl покажет ключ вместо текста.
